# Pair Sum — টার্গেট যোগফল সহ জোড়া সংখ্যা

ফাইল: `o_pair_sum.py`

---

## সমস্যাটা কী?

`t` টা টেস্ট কেস আছে। প্রতিটা টেস্ট কেসে:
- `n` টা সংখ্যা দেওয়া থাকবে
- একটা টার্গেট `x` দেওয়া থাকবে

আমাদের কাউন্ট করতে হবে এমন কতগুলো জোড়া `(i, j)` আছে যেখানে `i < j` এবং:

```
nums[i] + nums[j] == x
```

অর্থাৎ যেসব জোড়ার যোগফল ঠিক `x` হয়, তাদের সংখ্যা বের করতে হবে।

### ইনপুট ফরম্যাট

```
t                ← টেস্ট কেস সংখ্যা
n                ← কতগুলো সংখ্যা
a1 a2 ... an     ← সংখ্যাগুলো
x                ← টার্গেট যোগফল
```

### উদাহরণ

```
nums = [1, 2, 2, 3],  x = 4

জোড়াগুলো: (1,3)  এবং  (2,2)  ← index 1 ও 2-এর দুইটা 2 নিজেরা একটা জোড়া
উত্তর: 2
```

---

## Approach 1 — Hashmap (কোডে কমেন্ট করা আছে), O(n)

সবচেয়ে দ্রুত পদ্ধতি। বাম থেকে ডানে হাঁটি এবং একটা `seen` ডিকশনারিতে রাখি — **এখন পর্যন্ত কোন সংখ্যা কতবার এসেছে**।

```python
seen = {}
count = 0
for s in nums:
    a = int(s)
    count += seen.get(x - a, 0)   # আগে x-a কতবার এসেছে? প্রতিটার সাথেই a একটা জোড়া
    seen[a] = seen.get(a, 0) + 1  # এবার a-কে seen-এ ঢুকিয়ে দিই
```

### মূল আইডিয়া

বর্তমান সংখ্যা `a`-এর জন্য জিজ্ঞেস করি: *"আমার জোড়া হতে `x - a` লাগবে। আগে এটা কতবার দেখেছি?"* যতবার দেখা গেছে, ততগুলো নতুন জোড়া তৈরি হয়েছে।

### কেন ডুপ্লিকেট ঠিকভাবে কাউন্ট হয়?

যেহেতু আমরা জোড়াটা **আগে কাউন্ট করি, তারপর সংখ্যাটা ঢোকাই**, তাই একটা সংখ্যা কখনো নিজের সাথে জোড়া হয় না। যেমন `x = 4`, সংখ্যা `2`:
- প্রথম `2` এলে: `seen[2]` ছিল 0 → কোনো জোড়া না, তারপর `seen[2] = 1`
- দ্বিতীয় `2` এলে: `seen[2]` এখন 1 → **১টা জোড়া** `(2,2)`, তারপর `seen[2] = 2`

**সময়:** O(n) প্রতি টেস্ট কেসে, **জায়গা:** O(n)

## Approach 2 — Sort + Two Pointers (এটাই চালু আছে), O(n log n)

কোডে যে অংশটা আসলে রান হয়।

### ধাপ ১: সাজানো

```python
arr = sorted(int(v) for v in nums)
```

অ্যারে ছোট থেকে বড় সাজালে একটা সুবিধা হয় — সবচেয়ে ছোটটা বামে, সবচেয়ে বড়টা ডানে। তারপর দুই পাশ থেকে চিহ্নিতকারী (pointer) নিয়ে ভেতরের দিকে হাঁটা যায়।

### ধাপ ২: দুই পয়েন্টার

```python
left, right = 0, n - 1
while left < right:
    s = arr[left] + arr[right]
    if s < x:     # যোগফল ছোট → বড় সংখ্যা দরকার → বাম সরাও
        left += 1
    elif s > x:   # যোগফল বড় → ছোট সংখ্যা দরকার → ডান সরাও
        right -= 1
    else:         # ঠিক মিলে গেছে!
        ...
```

### কেন এটা কাজ করে?

যেহেতে অ্যারে sorted:
- যোগফল ছোট হলে বামটা ডানদিকে সরালে যোগফল **বাড়ে** (বামের সবচেয়ে বড় উপলব্ধ সংখ্যা)
- যোগফল বড় হলে ডানটা বামদিকে সরালে যোগফল **কমে**

অর্থাৎ প্রতি ধাপে সঠিক দিকেই এগোই — কোনো ভ্যালিড জোড়া মিস হয় না।

### ধাপ ৩: ডুপ্লিকেট হ্যান্ডলিং (সবচেয়ে গুরুত্বপূর্ণ অংশ!)

`arr[left] + arr[right] == x` হলে সরাসরি `count += 1` করলে **ভুল হতো** — কারণ একই মান একাধিকবার থাকলে একাধিক জোড়া তৈরি হয়। যেমন `arr = [2, 2, 2, 2]`, `x = 4` হলে জোড়া সংখ্যা ১ না, **C(4,2) = 6**!

তাই ম্যাচ পেলে দুইটা কেস:

**কেস A: পুরো ব্লক একই মানের** (`arr[left] == arr[right]`)

বাম আর ডান পয়েন্টারের মাঝের সবগুলোই একই মান। `m` টা সমান সংখ্যা থেকে জোড়া বানানোর উপায়:

```python
m = right - left + 1
count += m * (m - 1) // 2   # C(m, 2) = m জিনিস থেকে ২টা বাছাই
break                       # ভেতরে আর কিছু নেই, শেষ
```

**কেস B: দুই পাশে আলাদা আলাদা রান**

যেমন `[2, 2, 3, 3, 3]`, `x = 5` — বামে ২টা `2`, ডানে ৩টা `3`। প্রতিটা `2` প্রতিটা `3`-এর সাথে জোড়া হয়:

```python
cl = 1
while arr[left + 1] == arr[left]:   # বাম পাশের সমান মানের রান গুনি
    cl += 1
    left += 1
cr = 1
while arr[right - 1] == arr[right]: # ডান পাশের রান
    cr += 1
    right -= 1
count += cl * cr    # 2 × 3 = 6টা জোড়া একবারেই!
left += 1
right -= 1
```

### সম্পূর্ণ উদাহরণ দিয়ে ট্রেস

`arr = [1, 2, 2, 3]`, `x = 4`:

| left | right | যোগফল | সিদ্ধান্ত |
|------|-------|--------|-----------|
| 0 (1) | 3 (3) | 4 ✓ | কেস B: cl=1, cr=1 → count += 1×1 = 1; left=1, right=2 |
| 1 (2) | 2 (2) | 4 ✓ | কেস A: m=2 → count += 2×1/2 = 1; break |

ম্যানুয়ালি গুনলে: `(1,3)` একটা + দুইটা `2` থেকে `(2,2)` একটা = **2** ✓

আরেকটা উদাহরণ — `arr = [2, 2, 2, 3]`, `x = 5`:

| left | right | যোগফল | সিদ্ধান্ত |
|------|-------|--------|-----------|
| 0 (2) | 3 (3) | 5 ✓ | কেস B: cl=3 (তিনটা 2), cr=1 → count += 3×1 = 3; left=3, right=2 |
| — | — | — | left < right ভাঙে, লুপ শেষ |

ম্যানুয়ালি: প্রতিটা `2` প্রতিটা `3`-এর সাথে জোড়া → `(0,3), (1,3), (2,3)` = **3** ✓

(খেয়াল করুন — এখানে দুইটা `2` মিলে `4` হয়, `5` না, তাই সেগুলো কাউন্ট হয়নি। কেস A তখনই দরকার হয় যখন ম্যাচের পর `left..right` পুরো ব্লকটাই একই মানের হয়, যেমন আগের উদাহরণের `(2,2)` অংশ।)

## দুই Approach-এর তুলনা

| বিষয় | Hashmap | Sort + Two Pointers |
|------|---------|---------------------|
| সময় | **O(n)** ⚡ | O(n log n) |
| জায়গা | O(n) | O(n) (sorted কপি) |
| ডুপ্লিকেট | স্বয়ংক্রিয়ভাবে সঠিক | হাতে হ্যান্ডেল করতে হয় (রান গুনে) |
| কোড জটিলতা | খুব সহজ | মাঝারি |
| মূল অ্যারে | অপরিবর্তিত থাকে | sorted কপি লাগে |

Hashmap কমপ্লেক্সিটিতে ভালো, কিন্তু two pointers শেখা জরুরি — কারণ sorted অ্যারের অনেক সমস্যা (3-sum, 4-sum, container with most water ইত্যাদি) এই প্যাটার্ন দিয়েই সমাধান হয়।

## অন্যান্য টেকনিক্যাল বিষয়

### দ্রুত I/O

```python
data = sys.stdin.read().split()
```

`input()` বারবার কল করার বদলে পুরো ইনপুট একবারে পড়ে টোকেনে ভাগ করা হয়, আর `idx` পয়েন্টার দিয়ে টোকেন ধরে ধরে পড়া হয়। বড় ইনপুটে (competitive programming) এতে অনেক সময় বাঁচে।

উত্তরগুলোও `out` লিস্টে জমা রেখে শেষে একবারে প্রিন্ট:

```python
out.append(str(count))
print("\n".join(out))
```

### জটিলতার সারসংক্ষেপ

- **প্রতি টেস্ট কেস:** O(n log n) (two pointers) বা O(n) (hashmap)
- **মোট:** O(t · n log n)
- **এক্সট্রা স্পেস:** O(n)
